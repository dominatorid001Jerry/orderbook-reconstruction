## 三、为什么两只票不能算「截面 IC」

这是本次作业最容易做错的地方，必须讲清楚：

| | 截面 IC | 时序 IC |
|---|---|---|
| 比较对象 | **同一时刻**，不同股票之间 | **同一只股票**，不同时刻之间 |
| 需要多少样本 | 每期至少 20–30 只 | 一只股票就够（要足够多时点） |
| 2 只票会怎样 | 每期只有 2 个点，相关系数只能是 ±1 | 正常，可以算 |

所以两只票的正确做法是 **时序 IC**（`ts_ic`），而 `--panel` 那个参数是用来演示「样本足够时截面 IC 长什么样」的对照组。

> 如果老师其实要的是截面 IC，那就得扩到全市场 4000 只——这一点需要你和老师确认。

## 四、⚠️ 关于「模拟数据」

**你手上还没有真实的 Level-2 逐笔数据**，所以 `sim_feed.py` 会按**深交所字段结构**造一份可控数据。

- 用途：**验证代码正确**（这一点它做得很好，校验 169/169 全对）；
- 不能用途：**得出市场结论**（价格是随机游走 + 我人为注入的一点知情交易，IC 为正是我设计出来的）。

拿到真数据后只换输入层，`book / replay / validate / factor` 一行不用改。

## 五、真实数据怎么放（关键）

**先体检，再使用**：

```powershell
python check_data.py 000001
```

它会告诉你三件事：字段全不全、序号连不连续（丢包检测）、成交能不能对上委托。
最后给结论：✅ 可完整重建 / ⚠️ 只能近似 / ❌ 不能重建。

把文件丢进 `data/`，**文件名包含代码即可**：

```
data/000001_orders.csv      逐笔委托
data/000001_trades.csv      逐笔成交
data/000001_snaps.csv       十档快照（可选，有才能校验）
data/000002_orders.csv
data/000002_trades.csv
```

也认中文名（`000001_委托.csv` / `000001_成交.csv`），列名中英文都行：

| 内部字段 | 认得的写法 |
|---|---|
| `ChannelNo` | 频道号 / channel_no / channel |
| `ApplSeqNum` | 应用序号 / 序号 / seq / ApplSeqNum |
| `TransactTime` | 委托时间 / 成交时间 / 09:25:00.123 / 92500123 / 2026-01-05 09:25:00.123 |
| `Price` | 价格 / 成交价 / 委托价 |
| `OrderQty` | 委托数量 / 数量 |
| `TradeQty` | 成交量 / 成交数量 |
| `Side` | 买卖方向 / 方向（1买 2卖，或 B/S 都认） |
| `OrdType` | 委托类型 / 订单类型（1市价 2限价 3本方最优） |
| `ExecType` | 成交类型 / 执行类型（4成交 F撤单） |
| `BidApplSeqNum` / `AskApplSeqNum` | 买方委托序号 / 卖方委托序号 |

**已知坑（已修）**：CSV 里 `'000001'` 会被 Excel/pandas 当数字读成 `1`，代码前导零丢失。`data_loader` 已强制补零成 6 位，但你自己的文件最好按文本存。
